# My Little World（Unreal Engine 版）

一个正在开发中的 3D 虚拟世界项目，使用 **Unreal Engine 5 与 C++** 构建。

项目从第一人称漫游和物件交互开始，后续目标是让用户通过**文字描述或参考图片**创建个性化 3D 资产，将资产放入世界，并继续赋予它名称、故事与交互内容。

这个项目既是我的学习与开源项目，也是我准备用于大学申请的个人作品。我会持续记录设计取舍、失败案例、实验数据和个人贡献，而不只展示最终效果。

> **项目状态说明：** 当前仓库的核心是 UE 第一人称漫游与交互系统。AI 模型生成、自动资产处理和游戏内生成界面仍属于研发计划，不视为已经实现的功能。

## 项目目标

希望解决的不只是“用 AI 生成一个模型”，而是完整流程中的工程问题：

- 如何让文字和图片进入统一的生成流程；
- 如何异步执行耗时任务，避免阻塞游戏；
- 如何自动检查、优化和规范化生成结果；
- 如何将 GLB 资产可靠地导入 Unreal Engine；
- 如何设置合理的尺寸、坐标、材质、碰撞与性能预算；
- 如何保存资产来源、生成参数和场景状态；
- 如何评价模型质量、生成速度与游戏内可用性。

## 当前功能

以下功能对应当前 C++ 基础代码：

- 第一人称漫游：WASD 移动、鼠标控制视角；
- 视线检测：从相机向前发射交互射线；
- 按 E 与注视的可交互物件交互；
- `InteractableActor`：通过静态网格和文字消息构成可交互物件；
- 可配置交互距离与物件消息。

## 规划中的系统结构

```text
用户文字 ──→ 提示词整理 ──→ 概念图 ──┐
                                    ├─→ 图生 3D 模型
用户图片 ──→ 输入检查与背景处理 ────┘
                                             ↓
                                      原始 GLB 与生成记录
                                             ↓
                            网格检查、优化、归一化、预览
                                             ↓
                                  标准 GLB 与资产清单
                                             ↓
                              UE 导入、碰撞、LOD、交互
```

生成服务与 UE 客户端计划分离。这样可以根据实验结果替换本地模型或云端服务，而不需要重写整个世界交互系统。

## 运行当前基础版本

### 环境要求

- Unreal Engine 5，具体版本以项目 `.uproject` 为准；
- Windows 开发环境；
- Visual Studio Community 2022；
- Visual Studio 的“使用 C++ 的游戏开发”工作负载；
- 支持项目所用 UE 版本的 MSVC 与 Windows SDK。

当前基础漫游和交互代码不依赖 AI 模型，也不要求安装 glTF、Python 或运行时导入插件。

### 编译与打开

1. 克隆仓库；
2. 确认 UE 项目名为 `MyLittleWorld`，与 C++ 模块名一致；
3. 右键 `MyLittleWorld.uproject`，选择 **Generate Visual Studio project files**；
4. 打开生成的解决方案并编译，或双击 `.uproject` 后按提示编译；
5. 在 UE 编辑器中点击 **Play**。

如果仓库只包含 C++ 源文件而没有完整 `.uproject`、配置和内容文件，需要先在 UE 中创建同名 C++ 项目，再通过编辑器创建对应类并替换源码。不要手工猜测或修改 `.generated.h` 文件。

### 输入映射

在项目设置的 Input 中配置以下映射。

**Axis Mappings：**

| 名称 | 按键 | Scale |
|---|---|---:|
| MoveForward | W | 1.0 |
| MoveForward | S | -1.0 |
| MoveRight | D | 1.0 |
| MoveRight | A | -1.0 |
| Turn | Mouse X | 1.0 |
| LookUp | Mouse Y | -1.0 |

**Action Mappings：**

| 名称 | 按键 |
|---|---|
| Interact | E |

### 设置默认角色

1. 打开 World Settings；
2. 设置或创建 GameMode；
3. 将 **Default Pawn Class** 设为 `MyWorldCharacter`；
4. 点击 Play。

## 操作方式

| 输入 | 作用 |
|---|---|
| W / A / S / D | 移动 |
| 鼠标 | 调整视角 |
| E | 与注视的可交互物件交互 |

## 代码导读

### `MyWorldCharacter.h/.cpp`

玩家角色，负责：

- 相机组件；
- 第一人称移动与视角；
- 输入绑定；
- 交互射线检测；
- 交互提示与消息显示。

### `InteractableActor.h/.cpp`

可交互物件基类，负责：

- 保存静态网格组件；
- 提供可编辑的 `Message`；
- 设置可见性碰撞响应，使交互射线能够检测到物件。

后续 AI 资产功能应尽量通过新模块扩展，避免把网络请求、生成服务和文件处理全部堆入角色类。

## AI 模型选型原则

项目尚未预先认定某一个模型为最终方案。候选模型将使用相同输入和统一记录方式进行比较，主要考察：

- 输入符合度与视觉质量；
- 几何完整性与纹理可用性；
- 生成耗时、显存占用与文件大小；
- 自动后处理所需工作；
- UE 导入成功率与游戏内表现；
- 安装、复现和自动化难度；
- 代码、权重和生成结果的相关许可。

“代码公开”“开放权重”和“允许所有用途”不是同一件事。每个候选方案都需要单独核查许可证，失败案例也会保留在实验记录中。

## 资产来源与许可记录

项目不再笼统假设所有场景模型均为 Blender 手工制作。资产可能来自以下来源：

- 自己使用 Blender 制作的模型；
- AI 辅助生成并经过人工或自动处理的模型；
- 获得授权的第三方资产。

每类资产应尽量记录来源、作者或模型、版本、生成参数、处理过程和许可信息。AI 生成结果不自动等同于无版权限制或可随意再分发。

精选资产可以纳入项目发布；模型权重、批量实验输出、缓存与完整原始数据集不应无差别提交到 Git。需要版本管理的大型二进制资产可考虑 Git LFS。
